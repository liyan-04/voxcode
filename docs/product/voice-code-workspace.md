# VoxCode 语音开发工作空间

Issue：#78。基于 master `5a7edf6` 和 #74 网页工作空间原型的产品设计；本文是目标方案，不代表功能已实现或真实链路已通过。用户最新要求优先于历史 native iPhone、Mac、Relay 方案：手机只使用浏览器，VoxCode、灵矽接入和 Codex 全部运行于服务器。品牌文案统一使用“灵矽”。

## 推荐：一个工作空间，两种输入，同一任务

用户通过手机或桌面浏览器打开 VoxCode，选择项目和任务，使用文字或语音直接描述开发需求。语音由服务器接入灵矽，经 MCP 调用服务器 Codex 能力；网页通过 VoxCode CLI HTTP API 查询和操作同一份任务状态。两种输入共享任务身份、历史、版本和结果，不能形成独立任务系统。

核心循环是：**选项目 → 说需求 → 看见实际行动 → 查看改动和检查 → 继续修改或验收**。默认以语音作为顺畅的命令入口、页面作为可见状态与证据入口。文字始终可用，语音故障不阻断已运行任务。

### 普通开发直接执行，风险操作单独授权

在明确的授权项目与任务内，“修复这个错误”“补测试”“把按钮改成蓝色”等普通开发指令无需反复保存草稿、点击确认。点击发送或用户明确说出执行指令就是提交意图；页面立即显示目标和已接收指令，可继续追问或停止。半句话、讨论选项、单纯询问不会自动变成执行指令；仅意图或目标不明时简短澄清。

以下动作单独授权：超出已授权项目或执行范围、扩大权限、不可逆删除、发布/部署、对外发送、购买等。授权卡列出具体动作、对象及影响，只对该次操作有效。普通文件编辑、测试运行不能因为使用语音被额外加一层机械确认。Codex 原有操作审批不得被灵矽自动代答；“已执行完成”“允许危险动作”“用户验收通过”是三个独立事实。

现有网页草稿/确认流程可作为过渡行为；直接提交必须待服务端意图、去重、目标约束和权限策略落地后启用，不能先在 UI 去掉确认。

## 信息结构

| 区域 | 桌面 | 手机浏览器 |
| --- | --- | --- |
| 全局栏 | 项目选择、连接状态、账户 | 固定当前项目及连接状态，点击切项目 |
| 任务导航 | 左侧项目内任务列表，需处理/进行中/历史筛选 | 首页任务列表，优先显示需授权、失败、待验收 |
| 当前任务 | 中央对话与阶段活动，底部文字/语音输入 | 独立任务页，目标标题与输入区保持可见 |
| 结果 | 右侧摘要、文件、Diff、检查与验收 | 任务页“对话/改动/检查”切换，验收区跟随结果版本 |

不把大麦克风宣传卡作为持续占据首屏的模块。未接通语音时显示简洁状态和原因，提供文字入口；未实现功能不展示可点击假入口。新任务采用标题、目标和项目三项足够的信息；不要求先填写复杂表单。创建后任务标题可自动概括，完整原话可追溯。

## 项目、连续对话与目标锁定

- 项目来自服务器预先授权的项目目录清单；界面显示友好名称，浏览器和灵矽不提交任意服务器路径。MVP 支持从少量已配置项目中切换，不做网页克隆仓库或任意目录浏览。
- 项目切换只改变当前视图与之后的输入目标，不迁移、取消或重新执行旧任务。运行任务在所属项目继续；全局可提示有其他项目正在运行。
- 一个任务对应一个持久 Codex 会话；“继续改”“按刚才的要求”继续当前任务。明确说“新建任务”才新建；会话无法恢复时显示原因，不能悄悄开启新会话并声称记得上下文。
- 录音/一句话开始时绑定项目、任务和上下文版本。期间切页面不会重定向这句话。MVP 在当前语音轮次结束前禁用项目/任务切换，并允许立即结束录音后再切换，避免复杂的跨目标队列。
- 对于“切到另一个项目继续”，先解析为导航请求，结束当前轮次，展示新目标后接受下一句；同名项目或任务只对歧义候选做一次选择。
- 用户在录音期间可以取消本句；用户停止 Codex 是独立按钮。“停止播放/录音”不等于停止代码任务，“停止任务”不等于撤销文件改动。
- 同一任务运行中收到下一句：查询立即响应；普通开发补充进入该任务的待发送消息，显示原文和顺序，不并发开启第二个 turn。用户可在派发前撤回队列消息。

### 与架构师对齐的最小上下文

服务端冻结 `context={projectId,scopeId?,taskId?,turnId?,contextVersion}`，每次开始录音生成 `captureId` 并绑定该上下文。网页先同步语音会话目标，再允许录音；MCP 目标由服务端会话映射注入，模型不能改写。结果快照绑定 task、turn、revision；验收引用 `snapshotId+revision`，避免验收正在变化的工作目录。字段和接口的正式定义由架构文档及协调者维护，本文只表达用户可观察约束。

## 保留现有风格，补齐项目内微调

保留 #74 当前页面的留白、侧栏、任务列表和详情面板风格，只增加工作上下文，不变成项目管理平台。信息层级为 **项目 → 子项目范围（scope）→ 任务 → 结果版本**。子项目可以是前端、后端或共享包，是服务器预配置的项目内范围；没有子项目的仓库直接显示“全项目”。任务仍是执行与对话单位，特定文件是任务的修改目标，不再新增一套文件任务系统。

输入区上方增加轻量上下文条，例如“商城 / 前端 / 登录页任务 / 基于结果 v3”，手机一行省略、点击展开，桌面显示完整。创建任务可选“全项目”或一个子项目，详情同时显示范围；范围选择不是新导航大页。全项目任务允许协调多个 scope；子项目任务明确优先修改该范围，若必须修改共享配置或其他 scope，先说明必要性并请求一次扩展范围授权，不能默默越界。范围不是底层安全沙箱保证，真正文件边界由服务端策略执行。

“只改按钮间距”“这个错误提示再短一点”等增量要求，在当前任务继续：保留原始目标、原验收条件和已完成内容，新增本轮约束，而非重写任务或从零生成。上下文条显示修改基于哪个结果版本；用户可以在结果版本上点“基于此版本微调”，带入 `baseSnapshotId`，再输入短指令。该字段标记修改参照，不意味着自动 checkout、回滚或覆盖之后的改动；MVP 只允许基于最新结果微调；旧版本参照返回冲突，提示切换到最新结果，不能自动合并、cherry-pick 或覆盖新工作。

新版本继承原验收条件，受本轮影响的检查需要重新运行，其他条件保留来源并标记“沿用/待复核”，不能把旧版本通过状态冒充本轮检查。页面优先展示“本轮改动”和“全部改动”两个结果视角；MVP 可先只实现当前版本 Diff 与原验收条件的可追溯记录，本轮独立 Diff 尚未具备时必须标明。

与架构合同对齐：微调提交携带 `requestId/expectedRevision/contextVersion/projectId/scopeId/taskId/baseSnapshotId/deltaPrompt`，文件选择使用结果清单内的 `selectedFileIds`；原验收条件仅在用户明确提出 `criteriaDelta` 时改变。`scopeId` 与 `baseSnapshotId` 由服务端校验：scope 来自当前项目 registry，参照快照必须属于当前任务/项目；语音会话同步 scope，录音期间同样锁定。特定文件仅可从授权范围内的结果文件列表选择，或用自然语言描述，不能让浏览器传任意绝对路径。预览中选中元素、截图圈选、DOM/样式上下文作为后续增强；MVP 不承诺“点哪里就改哪里”，也不伪造元素关联。

子项目共享同一个 Git 边界时，不保证可以安全并发：前后端可能同时修改锁文件、共享类型、构建配置。保持每任务独立工作区；scope 不能替代任务隔离、冲突检测和最终整合。MVP 使用保守的同仓库写任务串行策略，等待授权与停止中同样持有仓库写锁；确需跨任务并发时由统一调度器校验基础版本和受影响文件，不能仅凭 scope 名称不同放行。UI 显示“等待同仓库任务完成”，不用误导性“后端离线”。

界面交付先做上下文条、scope 选择、结果版本“微调”入口及示例短指令；后端契约落地前作为明确标识的设计预览，不能连到旧 API 后声称目标锁定已实现。随后实现单 scope 真实闭环，最后才增强跨 scope、预览选中元素与本轮 Diff。

## 状态、反馈与恢复

页面同时呈现服务器连接、语音连接和当前任务状态，避免一个绿点暗示全部链路可用。语音状态包括未连接、连接中、可录音、录音中、处理中、播报中、失败；任务状态包括排队、执行中、等待授权/输入、停止中、已中断、失败、完成待验收、已验收。

运行时展示“正在检查文件”“正在运行测试”等有真实事件支持的活动；没有事件则显示最近更新时间，不造进度百分比。语音先显示原话/识别文本，再显示已发送指令及目标；关键结果可播报简短摘要，完整日志留在页面。识别内容与用户修正内容可区分，不用迟到转写覆盖用户输入。

| 异常 | 用户可见反馈与恢复 |
| --- | --- |
| 麦克风拒绝、浏览器不支持、语音服务离线 | 明确原因，切换文字；已提交任务继续运行 |
| 网络断开或切后台 | 显示最后同步时间；不显示任务失败，不自动重放录音/播报 |
| 提交超时，不知是否成功 | 显示“确认提交结果中”，用同一个请求身份对账；用户重试不重复建任务 |
| 服务器重启 | 重连后恢复列表、任务身份和可恢复历史；未确认结束的执行标记中断/待恢复，禁用重复派发 |
| 目标版本变化 | 保留本句内容，显示原目标与当前版本；明确重新绑定后再提交 |
| Codex 失败/取消 | 保留已产生改动和证据，展示原因；继续任务是新 turn，不伪装回滚 |

手机浏览器 MVP 不承诺锁屏/后台持续录音或语音不断线。进入后台结束录音并清理播放；重新打开恢复任务状态。真实手机权限、弱网、电话中断需设备验证。

## Diff、测试与验收

完成态首先给出短摘要：做了什么、改了哪些文件、跑了哪些检查、仍有什么缺口。摘要来自该任务该版本，不能把模型“测试通过”当作真实检查证据。

结果最小集合：变更文件列表、增删统计、可展开的文本 Diff；每项检查的命令、执行状态、退出码及有界输出；未运行/输出截断明确标记。二进制文件标记无法文本预览，不强行生成 Diff。证据由服务器采集，按任务版本固定保存，不能因后续 turn 修改而覆盖上次结果。

验收区提供“继续修改”和“接受此版本”。用户浏览真实证据后可接受，无需再次弹窗；“接受”只记录当前版本已验收，不隐含 commit、merge 或部署。后续修改产生新版本，旧验收保留为历史，新版本重新待验收。必需检查失败或未验证时显示阻断原因；可选检查可以带说明验收，规则由项目明确配置。

## 最小实现顺序与可验收交付

| 顺序 | 产品交付 | 通过条件 |
| --- | --- | --- |
| 1 | 网页/API 与 MCP 同源任务身份和上下文契约 | 两个入口创建/查询同一任务；目标、版本、请求去重和权限有回归验证 |
| 2 | 项目选择、持续任务与普通开发直达 | 两个预配置项目可切换；语音和文字可持续同一 Codex 会话；跨项目输入不能串线 |
| 3 | 真实语音最小闭环 | 手机录一句→灵矽 MCP→Codex 执行→网页见状态/摘要；真实 TTS 可听另列证据；语音失败可文字继续 |
| 4 | 结果文件、Diff、检查、版本验收 | 一次真实修改及检查形成不可混淆证据；接受不触发合并；继续产生新版本 |
| 5 | 弱网与中断打磨 | 提交重试不重复执行；切后台/项目不串线；重启可对账，未知运行状态不伪称成功 |

这些是功能增量顺序，不允许为了先做 UI 而省略首步任务身份和权限底座。每步独立 Issue/PR、明确拥有路径、依赖、真实验证环境；功能通过本地测试与独立评审后才进入下一步真实联调。桌面与手机共用一套响应式页面和 API，不维护第二套 native 客户端；不同时发展旧 Relay/Connector/设备 WSS 主链路。

## 当前实现与承诺边界

本次只阅读了 #74 网页原型 `apps/server/public/index.html` 和 master 既有协议文档，未运行服务或进行真实设备验证。原型已有登录、任务列表、文字草稿、确认、取消、轮询和输出展示；语音入口禁用，明确提示 Diff/文件/检查证据未采集。项目选择已有 #74 本地 API/UI 实现但未部署验收；持续追问、真正语音、完整证据和验收仍需实现与验证，不得在产品文案中标成已可用。

历史合同中的设备侧语音/原生客户端，以及早期“所有 MCP 写操作都要求网页二次确认”的建议，不构成本文新设计的完成证据；实施时由协调者统一更新共享契约，不能让网页与 MCP 各自推导权限。无需重写成熟的 Codex 调度器：优先复用 CLI API 已有任务/权限能力，缺少的项目与证据契约统一补齐。

MVP 不包含在线编辑器、任意文件管理、仓库创建/克隆、多用户协作、自动合并部署、复杂监控、后台唤醒和跨服务器调度。后续先提升语音意图与恢复质量，再考虑项目配置管理与通知；不能用扩大功能掩盖未完成的真实链路验收。

## 任务树交互补充

按用户最新要求，左侧展开项目与任务/子任务，点击打开任务标签。关闭标签保留任务上下文；每任务独立文字草稿与语音入口。归档从默认列表隐藏，停止仅停止执行，删除采用用户确认的可恢复标记，不删仓库文件或历史；运行/清理未确认的任务先停止。父任务删除不连带子任务。metadataRevision 与 CLI revision 分离。语音未连接和续聊未验证时如实显示不可用，不冒充已执行。
