# VoxCode 手机演示版方案

> 历史范围说明（2026-10-24）：本文记录旧的原生手机演示方案。当前实现以[手机、Mac 与 Linx 当前架构](architecture/phone-mac-linx-current.md)、[Mac Agent 控制面合同](architecture/mac-agent-control.md)和实际代码树为准；本文中的原生 iOS、旧 Relay、固定公网地址和草稿确认步骤不再是当前实现入口。

日期：2026-10-23。用户确认“手机上打开 app 演示就可以”。本文是当前首版范围，替代早期完整方案中的网页预览、Mac 工作台和大屏必交要求。目标能力仍需实际验证，不代表已经完成。

## 演示目标

在原生 iPhone VoxCode App 内完成：**说需求 → 确认任务 → 查看执行进度 → 查看代码改动与测试结果 → 追问修改或验收。**

手机展示的是 VoxCode 本身。首版不要求在手机运行或交互预览 Codex 生成的网站。任务可选择小型代码修改、带明确检查命令的缺陷修复或测试补充，结果通过真实 diff、文件列表、检查命令、退出码和关键输出检验。

## 三个交付部分

| 部分 | 职责 |
| --- | --- |
| 原生 iPhone App | 配对、录音和确认、任务列表与切换、进度、结果与验收 |
| 一个服务器TLS入口 | Relay认证后转发手机与同机任务/语音服务通信 |
| 一个同机任务/语音入口 | 管理Connector、任务调度、本地Codex stdio子进程、灵矽WSS及结果 |

Codex 是本机已有执行依赖，灵矽 AI 是已有语音服务。服务器任务服务与同机Connector统一启动和退出，保持 App Server 本机 stdio、桥接服务回环监听的边界。

## 必须保留

- 原生 iOS 交付；指定 iPhone 的签名安装单列验证。未签名模拟器构建不能当作安装包。
- 户外手机开启用户VPN连接vm6 `https://203.0.113.10:9899`；服务器本机运行Codex。凭据与音频使用严格校验的TLS，VPN不替代鉴权，无需域名。
- 灵矽 AI 负责语音识别、待确认指令、真实进度查询和前台请求的结果播报。先验证一条真实语音闭环，再完善短轮次澄清；模型不能自动提交代码指令、允许操作或验收结果。
- 至少管理 20 个任务，默认四个执行名额、配置范围 1–8；超额排队，同一任务只有一个活跃 turn。任务独立工作区和版本证据，首版不自动合并任务。
- 录音固定任务与版本；切页不能改指令归属。提交响应不确定时沿用原 requestId 和原内容对账，不能重复执行。
- 追问继续同一个 VoxCode 持有的 Codex 会话。未知派发、恢复失败和旧执行未确认终止时明确阻断，不能静默替换上下文。
- 手机接收真实状态、变更摘要、包含新增文件的 diff、测试命令/退出码/输出和版本化验收条件。执行完成、操作授权和用户验收分别记录。
- 取消保留“停止中”直到确认终止；断线后恢复快照。工作区不能当作完整安全沙箱。

## 手机四个页面

| 页面 | 首版内容 |
| --- | --- |
| 连接 | 服务器/项目、配对、在线状态、最后同步时间；并发设置可在此提供 |
| 任务列表 | 全部、执行中、排队、待处理；短编号、状态和最近活动；运行数与排队数 |
| 任务详情 | 动态/结果、语音入口、目标任务、允许/拒绝操作、停止、追问 |
| 结果验收 | 变更文件、diff、检查结果、逐条人工确认、接受当前版本 |

前台同步即可；不承诺锁屏常驻录音、后台即时推送或自动播报。录音失败、来电、切换输入或重新录音不得被旧回调污染。

## Benchmark 和轻量监控

Benchmark 是首版工程交付，使用可重复脚本和机器可读报告；不引入性能平台。至少记录 24 个任务管理、四路调度/排队、重放去重、取消完成，以及创建/列表/状态 API 的样本数、p50/p95/p99 和错误数。功能不变量包括不超名额、不串任务、不重复执行、停止确认后才释放名额。

报告必须标明 Git revision、运行环境、任务数、执行名额、样本量和依赖类型。受控执行器测的是桥接/调度开销；真实 Codex、灵矽语音和蜂窝端到端耗时另列。先建立基线，性能门槛根据实测设定，不能提前编造结果或承诺速度。

服务端监控先提供受认证的聚合状态：连接、运行/排队/等待/停止/失败计数、请求耗时和错误数。时间允许时增加一个简单状态页；完整监控平台不进入关键路径。禁止输出提示词、代码、令牌、私有路径或无限增长的任务标签。

## 延后范围

- 手机内可交互网页、WKWebView、预览 cookie/产物发布与通用开发服务器代理。
- 完整 Mac Web 工作台、独立预览服务、全面性能平台和复杂监控看板。
- App 自行发现/控制 AirPlay 接收端、后台推送、任意仓库运行和已有 Desktop 聊天接管。

旧预览接口与未完成文件可以保留为后续工作，不进入手机演示版验收或默认启用。用户于2026-10-24明确本次不限制AirPlay协议；屏幕展示可另行选择，不阻断原生手机核心闭环。

## 验收与演示

1. 指定 iPhone 能打开签名原生构建，完成连接、录音与任务页面操作。
2. 一次真实灵矽语音形成草稿，用户确认后 Codex 实际修改授权项目；手机显示真实 diff 和检查结果。
3. 对同一任务追问，保留原会话，展示新版本并人工验收；旧结果不能充当新版本证据。
4. 浏览和切换至少 20 个任务；四个独立任务执行，第五个排队。至少十次混合目标指令没有错误归属。
5. 断网恢复、相同请求重试、操作授权和停止都具有实际记录；手机蜂窝+VPN到服务器的链路单独实测。
6. Benchmark 留下可重复命令和真实报告，模拟/受控依赖明确标注。各端完成两名独立 reviewer 评审。

三到五分钟演示：打开 VoxCode → 语音发任务并确认 → 切换并行任务、查询进度 → 查看真实结果 → 语音追问 → 验收。较长执行可分段展示并说明剪辑。模拟演练必须醒目标识，不冒充真实 Codex、灵矽或外网验证。

## 执行顺序与当前限制

先验证安装路径、真实 Codex 修改/续接、灵矽录音/播报；开发阶段可使用明确标识的模拟环境。随后并行完善 iOS、Mac 和 Relay，最后跑基准、两轮独立评审和真机演练。架构师协调三个开发 agent，协调者维护共享接口、集成与提交。

当前已有云端未签名模拟器构建通过记录，但指定iPhone签名安装、真实灵矽和服务器真实Codex闭环仍未验证。不能通过简化方案把这些现状改写成已完成。用户已授权通过liyan-server在vm6验证/部署本项目；更新前核对203.0.113.10:9899现有进程归属，无关服务占用就停止并通知。旧bili-xs8入口和历史暂缓指令不作为当前部署指令。
