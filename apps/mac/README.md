# Mac bridge

Requires Node >=22, Git, installed/authenticated Codex CLI (protocol checked against 0.154.0). No npm dependencies.

```sh
VOXCODE_PROJECT=/absolute/authorized/git/project VOXCODE_DATA=/absolute/private/state node apps/mac/cli.mjs
node --test apps/mac/test/*.test.mjs
```

The selected project must have a HEAD commit. The bridge creates detached worktrees from HEAD; uncommitted source changes are not copied. Each task retains its worktree and durable owned Codex thread. Follow-up messages resume that thread in the same worktree with the same approval and sandbox restrictions; unavailable resume fails explicitly. The bridge saves thread identity before dispatch and turn identity afterward. No existing Desktop chat is taken over. Cancellation requests interruption and process termination; edits already made remain. Execution completion and user acceptance are separate.

Execution concurrency is unlimited by a user-configured quota. Up to 32 tasks can be managed; each task still has only one active turn, and process ownership/recovery gates remain enforced. The legacy authenticated settings field `{requestId,executionLimit}` is retained for client compatibility and persistence, but no longer blocks dispatch.

Create and follow-up bodies may include 1-12 manual criteria with text of at most 500 characters and optional boolean `required`. Omitted create criteria supplies one required manual condition; omitted follow-up criteria preserves condition IDs/text but resets verification for the new version. Once completed, `POST /api/tasks/:id/criteria/:criterionId` takes `{requestId,version,decision:"pass"|"fail",note?}`. It records version-bound note evidence and invalidates the current acceptance. `POST /api/tasks/:id/accept` requires the completed current version, passed required criteria and no failed trusted command/check evidence. Failed trusted checks remain blocking even if earlier output is dropped by retention; a new execution version is needed to establish corrected results. Acceptance records the version, time and criterion/evidence references. Model response prose never marks a criterion passed. Follow-ups reset acceptance and preview metadata; prior evidence remains explicitly versioned and bounded.

Defaults: loopback 127.0.0.1:8787. `VOXCODE_HOST`, `VOXCODE_PORT`, `VOXCODE_DATA`, `VOXCODE_PROJECT` configure startup. LAN binding also requires `VOXCODE_TRUSTED_HTTPS=1`, asserting that the operator configured a trusted HTTPS reverse proxy/firewall. The bridge itself serves HTTP; do not expose its port directly. Pairing code printed locally expires after five minutes, rate limited to five attempts/minute/address and 256 attempts/minute overall. Session tokens are 256-bit random bearer secrets; only SHA-256 verifiers and per-session IDs/dates are persisted in mode-0600 state. Sessions expire after seven days, with at most 32 paired sessions. Legacy plaintext-token state is invalidated on startup and requires pairing again. Protect the state directory and backups.

`POST /api/unpair` with the current bearer revokes only that session and returns `{ok:true}`. Every subsequent authenticated request rejects it, without deleting tasks or affecting other phones. For local lost-phone recovery, send `kill -USR2 <bridge-pid>` (PID printed at startup) to revoke all paired sessions without deleting task history. Restart generates a fresh five-minute pairing code. Local service callers can inspect `sessions()` (IDs and dates, never verifiers), `revokeSession(id)` or `revokeAll()`.

`createServer(options)` returns `{server,service,close}`. Options include project/dataDir and optional `voiceHandler(req,res,sessionToken,service)`, called only after shared authentication. `service` exposes get/list/events/mutate/settings/configure/monitor; voice tools must retain frozen task/version/requestId binding and call mutate with explicit task identity. Public task and saved mutation responses omit private worktree and Codex thread/turn fields. Integration must subscribe to `service.onAuthorizationChange(listener)` and close voice sessions whose retained tokens no longer pass `authorize`; the method returns an unsubscribe function. Expiry notification occurs within 60 seconds, and authorization checks enforce expiry immediately. No preview file server is exposed; preview publication and workbench routes are deferred.

Authenticated loopback-only `GET /api/monitor` returns the exact contract aggregate: generation time, process uptime, execution capacity, active executions, recovery flag, all fixed status counts (including zeros), and actual process RSS/heap bytes. Completed excludes accepted tasks. Recovery includes task-specific unknown dispatch as well as global unresolved process ownership. These are current totals, not durable throughput counters; prompts, task identifiers/titles, events, paths and credentials are excluded. No monitoring platform, status page or relay exposure is implemented.

Snapshots, events and request replay are saved in one atomic rename before responses. Replay IDs are globally unique: equivalent JSON payloads return the original response regardless of property order; changed payloads conflict. A clean restart resumes queued tasks. Before any execution starts, the bridge persists an unconfirmed-execution record; it clears that record only after the executor confirms teardown. An abrupt restart with such records marks affected tasks interrupted but does not claim their processes stopped. It quarantines all scheduling, leaves queued tasks queued, and returns 503 with a local recovery diagnostic for new tasks and follow-ups. Read-only inspection and saved request replays remain available. Legacy snapshots with running/waiting/stopping tasks also enter this quarantine, which survives further restarts. JSON persistence is single-process only; never start two bridges on the same data directory. Atomic rename does not guarantee survival of abrupt power loss (no fsync).

A lost or invalid `turn/start` response is a separate task-level uncertainty. The adapter reports `dispatchUncertain`; the service persists a reconciliation requirement, marks the task interrupted and returns 503 for follow-up. A pending dispatch found on restart is treated the same way. It never automatically replays the prompt, creates a replacement thread or clears this state merely because the owned process terminated. Other tasks can continue after any global process-ownership quarantine is resolved. `recover.mjs --confirm-executions-stopped` clears only process-cleanup quarantine, not uncertain turn reconciliation. Automatic thread reconciliation is not implemented: keep that task blocked until a local operator has inspected its durable thread and an explicit recovery procedure is added. Do not edit private snapshots or use a new data directory to bypass an unknown turn.

### Unclean execution recovery

Stop the bridge before recovering. Inspect the affected tasks and their worktree paths in the private state directory. Use macOS Activity Monitor or `ps -axo pid,ppid,pgid,command` and `lsof` to identify the previous App Servers and their task processes by their live command, ancestry, process group and working directory. Stop those verified task processes and confirm that none remain; a completed Mac reboot is another way to establish that previous local task processes have exited. A saved PID alone is not proof of process identity. The bridge deliberately does not signal PIDs from persisted state, and closing a quarantined bridge does not clean up an earlier bridge's processes.

After verifying cleanup, run this local command with the same project and data directory:

```sh
VOXCODE_PROJECT=/absolute/authorized/git/project VOXCODE_DATA=/absolute/private/state node apps/mac/recover.mjs --confirm-executions-stopped
```

This flag is an explicit operator assertion that cleanup is complete; the command cannot verify it and refuses to run without the flag. It clears the scheduling quarantine without signaling processes, deleting tasks, modifying worktrees or rolling back edits. Restart the bridge afterward. Previously queued tasks may then execute; interrupted tasks require a new follow-up message. Never run recovery concurrently with a bridge or select a fresh data directory to bypass unresolved processes. Automatic crash teardown and OS-level containment remain unimplemented.

MVP retention is bounded: 32 tasks, an ordinary mutation threshold of 128 saved requests, a separate threshold of 128 saved settings requests, 64 recent events/task (monotonic cursors), 1 KiB/event, 16 KiB/evidence value and 64 KiB recent evidence/task. Structured command metadata is limited to status, bounded command, integer exit code and bounded artifact ID; each evidence item has a stable ID. Truncation and dropped earlier evidence are labeled. Exact saved replays remain available even after their quota is full; new work receives 429. Settings do not consume task-mutation capacity; request IDs still conflict across both budgets. Cancellation and decisions for already-offered approvals have reserved capacity beyond the task threshold. Each execution can offer at most 16 approvals, each accepting one saved decision; excess offers are declined locally. Approval accept/decline and exact replay remain available at the quota, while changed or reused decisions still conflict. Repeated stopping requests do not add storage. Worktrees still need operator cleanup. At the quota, stop the bridge, resolve execution and turn-reconciliation requirements, and archive the complete private data directory before selecting a fresh data directory; archived tasks are preserved for manual inspection. This deliberately avoids silently deleting replay IDs or unlimited synchronous JSON growth; automatic archive browsing is not implemented.

The real adapter starts one local stdio App Server per execution in its own POSIX process group. It uses initialize, durable thread/start or thread/resume, turn/start, turn/interrupt; local workspace-write sandbox and on-request approvals. Git and Codex child environments exclude all `GIT_*`, `LINX_*` and `VOXCODE_*` variables, including bridge/relay/voice tokens and configuration. Standard `PATH`/`HOME` and other user coding environment remain inherited; operators must intentionally select any additional credentials available to task processes. Shutdown sends TERM, waits one second, escalates the owned group to KILL, awaits child close and confirms process-group disappearance before releasing the slot. Service shutdown awaits executor settlement too. If ownership cannot be confirmed, the slot stays quarantined in stopping, all further scheduling pauses, and shutdown reports failure. This covers descendants retaining the owned process group; deliberately daemonized descendants that escape it require stronger OS containment and are not supported runtime resources. Preview processes are not launched by the bridge.

Command approvals expire in two minutes and are single-use. Empty or oversized commands fail closed. File-change escalation is always declined: installed Codex 0.154.0 sends itemId/reason/grantRoot but not the proposed changed content in that request, so the current phone approval contract cannot represent the full requested write scope accurately. Ordinary sandboxed file edits still work. Unsupported interactive requests return a protocol error and can be addressed by a follow-up message after the turn ends. Other elevation types are unsupported.

Evidence consists of real command outputs, responses, turn diffs and a final Git status/content snapshot captured after process shutdown. Command outputs are note evidence with actual command/exit metadata when available; a zero command exit is not inferred proof of every acceptance condition. Final content includes new untracked source files and tracked modifications/deletions, never staging changes. It is bounded to 200 files, 64 KiB/file and 256 KiB before the service retention limits; secret-like names, hidden paths, unsupported/binary files, symlinks and hardlinks are omitted with explicit labels. Paths must remain inside the canonical worktree, final opens reject symlinks, Git external diff/text conversion are disabled. This is conservative filtering, not a general secret detector: agent output and ordinary source text can still contain sensitive content the authorized task reads. No simulation mode is enabled by CLI; tests explicitly inject subprocess fixtures/executor adapters.

The restricted development sandbox cannot initialize Codex's SQLite runtime under ~/.codex; protocol smoke succeeded with approved runtime access. Full model edit, durable follow-up and four real parallel tasks remain separate integration gates; unit tests do not claim model execution verification.

Adapter fixture tests exercise a real subprocess and descendant ignoring TERM, confirmed termination, failed turns, initialize errors, malformed JSON, command/file decisions, child environment filtering and new-file evidence excluding `.env` and symlink content. Crash tests SIGKILL an actual service using the actual adapter, confirm that fixture descendants remain alive, verify restart quarantine and explicit local recovery, and cover legacy snapshots across repeated restarts. Auth tests cover two-device revocation, verifier-only persistence, expiry notification and HTTP unpair. Retention tests cover bounded evidence/events, cursor continuity, cancellation after the mutation budget fills, and bounded accept/decline decisions with durable replay at that budget. These fixture tests do not establish automatic crash teardown or a real Codex model turn.
